## 2.4a: note API

1. **Core** (`crates/fc-core/src/note/ops.rs`): `pub struct NewNote<'a> { deck, note_type, values:
   &'a [(Id, &'a str)], tags: &'a [&'a str] }` and `Collection::add_note_with(&NewNote) ->
   Result<AddedNote, NoteError>`. Clean the tags first (`tag::check`, a bad tag refuses the whole
   note), then note, cards and tag rows in one `self.write`. `add_note_to_deck` calls it with no tags.
   The tag write has to use the same `WriteTx`; if the tag code only offers a function taking
   `&Collection`, split out a `WriteTx` helper rather than duplicating the rules. A tag error needs a
   `NoteError` variant (or a wrapping one); say which in the notes.
   Tests: tags written with the note; a bad tag writes nothing (no note, no card, no tag); the
   `NoteAdded` event fires once; a merge from the change log has the tags (one `changes(All)` replay).
2. **CLI:** `fc add-note --tag` moves to `add_note_with`. Existing CLI tests must pass unchanged.
3. **`fc-api`** (`crates/fc-api/src/notes.rs`, new; `media.rs` or next to `getMedia`): `getNoteTypes`,
   `getTags`, `findDuplicates`, `addNote`, `addMedia` as in ADR 0011 decision 4. `kind` is a string
   union `"standard" | "cloze"`. `addMedia` reads the attachment; no attachment or an empty one is
   `invalidInput`. Plain messages for `NoCards { cloze }`, a missing deck or note type, a bad tag.
4. **Bindings** regenerated; `core-client` re-exports the new types.
5. Tests through `dispatch`: each method on a fresh collection, the error mappings, `addMedia` twice
   with the same bytes gives the same name and `new: false`, `addNote` with duplicates, no collection.

Checks: `cargo xtask check`. Nothing to see in a UI. Build notes in ADR 0011, STATUS.

## 2.4b: Add screen and editor (no media)

1. **Dependency:** add the ProseMirror packages listed in ADR 0011 "Consequences" to `packages/ui`,
   **exact versions** (`bun add --exact`). Say why in the PR. Check that `bun.lock` is the only
   lockfile.
2. **`packages/ui/src/editor/`:**
   - `schema.ts`: the schema from ADR 0011 decision 1. Image and sound nodes are in the schema now
     (so content with them loads and saves), with plain node views; 2.4c gives them real views.
   - `html.ts`: `loadField(html) -> Node` (inert `DOMParser`, then the schema parser) and
     `saveField(doc) -> string` (the storage rule: no wrapper for plain text, `<br>` between
     paragraphs, `<li>` content without `<p>`, `[sound:name]` for sound). `roundTrips(html)`: the
     "cannot represent" check (normalise whitespace and `<strong>`/`<em>` first).
   - `commands.ts`: bold, italic, the two lists (`prosemirror-schema-list`), Enter as line break
     except inside a list, cloze with a new number and with the current one (the highest `cN` across
     **all** fields of the note is passed in).
   - `FieldEditor.tsx`: one `EditorView` per field. Props: `value`, `onChange(html)`, `label`,
     `onFocus` (tells the screen which view the toolbar acts on). `aria-labelledby` the field label,
     `aria-multiline`. Scroll margin from the bottom action height (step 4).
   - `Toolbar.tsx`: buttons with `aria-pressed` for marks, `pointerdown` default prevented so the
     editor keeps focus, sideways scroll when it does not fit.
3. **`AddScreen`** (`packages/ui/src/screens/AddScreen.tsx`, replacing the placeholder):
   - deck `<select>` (from `getDeckList`, full paths) and note type `<select>` (`getNoteTypes`);
   - one `FieldEditor` per field; tags input with chips and suggestions (`getTags`, prefix match,
     ignoring case);
   - duplicate warning (400 ms debounce on the first field, `findDuplicates`), plus `addNote`'s own
     `duplicates`;
   - `BottomAction`: toolbar and Add; Ctrl+Enter adds; Add disabled while a call runs (a double tap
     adds once, as in 2.3);
   - after Add: clear the fields, keep deck, note type and tags, focus the first field, a
     `role="status"` line with the card count;
   - remembered deck and note type and the draft in `localStorage` (`fc.add.last`, `fc.add.draft`,
     try/catch, ignored when unreadable). A Clear button;
   - changing note type keeps values by field name and holds the rest in the draft.
4. **Keyboard:** on editor focus and on change of the shell's keyboard inset, scroll the focused
   editor into view above the bottom action. If the shell does not expose the inset or the bottom
   action height to screens, add that to the shell (a hook), not arithmetic in the screen. Say which
   in the notes.
5. **Tests (Vitest, happy-dom):** `html.ts` round trips (the cases of ADR 0011 finding 4, plus
   lists, `<br>`, two paragraphs, sound), `roundTrips` true and false cases, the cloze numbering
   (new, same, with a selection, without, across fields), the screen with a fake core: add, the
   duplicate warning, tags kept after Add, remembered choices, draft restore, the NoCards message,
   double tap.

Checks:
- `cargo xtask check`.
- **Web** (headless Brave over CDP, screenshots read): phone width and 1100 px, light and dark. Add
  a Basic note with bold, a list and two tags; add a Cloze note with two clozes; see both in Decks
  and study them; the duplicate warning; draft survives a reload.
- **Desktop** (`bun run dev`, WebKitGTK): the same note by keyboard only (Tab, Ctrl+B, Ctrl+Shift+C,
  Ctrl+Enter).
- **Phone:** build and install the debug APK, screenshot the empty Add screen. **Anthony checks**
  typing with his keyboards (Samsung Keyboard and Gboard if he has it): autocorrect, Backspace across
  bold text, lists, the cloze button, that the field being typed in stays above the keyboard and the
  toolbar, one-handed reach of Add, portrait and landscape.

## 2.4c: media

1. **CSP** (`apps/native/src-tauri/tauri.conf.json`): `img-src 'self' asset: data: blob:` and
   `media-src 'self' blob:`. Nothing else changes.
2. **`packages/ui/src/editor/media.ts`:** `prepareImage(file) -> { name, bytes }` (ADR 0011 decision
   3: JPEG always re-encoded at most 1600 px at 0.85; PNG resized only over 1600 px; GIF, WebP and SVG
   as they are; refuse what `createImageBitmap` cannot decode), `prepareSound(file)`, the 20 MB check.
   Keep the original file name's stem; a re-encoded file gets `.jpg`.
3. **Pickers:** hidden `<input type="file">` elements triggered by the toolbar's Image, Take photo
   (`capture="environment"`, shown only when `(pointer: coarse)` matches) and Sound buttons. Multiple
   images allowed, one sound at a time. After a pick, `addMedia`, then insert the node at the
   selection of the field that had focus.
4. **Node views:** image as an `<img>` with a `blob:` URL (from the picked bytes, or `getMedia` for a
   restored draft), revoked when the node view is destroyed; sound as a chip with the file name and a
   play button (`<audio>` with a `blob:` URL). Both deletable with Backspace and a remove button.
5. **Android:** in `MainActivity.onCreate`, delete `JPEG_*.jpg` older than one hour from
   `getExternalFilesDir(Environment.DIRECTORY_PICTURES)`. No manifest change.
6. **Tests:** `prepareImage` with fixtures (a rotated JPEG, a large PNG, a small PNG, a GIF, a file
   that does not decode; happy-dom has no canvas, so the image code takes an injectable encoder and
   the real encoder is checked in Brave), the size limit, inserting nodes, the saved field HTML
   (`<img src="name">`, `[sound:name]`), draft restore with media.

Checks:
- `cargo xtask check`.
- **Web:** pick an image (CDP `DOM.setFileInputFiles`) and a sound; the note's card shows both in
  Study; a rotated JPEG comes out upright and without EXIF (check with `exiftool` on the bytes from
  `getMedia`).
- **Desktop:** the GTK dialog opens from Image and Sound in the app (ADR 0011 finding 1 was
  MiniBrowser only); add a note with both and study it.
- **Phone:** build and install. **Anthony checks** Image (Gallery and Files are offered), Take photo
  (the camera opens, the photo lands in the field, upright), Sound from Files, the card in Study with
  both, and that the app comes back with the draft if Android closed it while the camera was open.
  Also note whether the picker is the Photo Picker or the older one.
