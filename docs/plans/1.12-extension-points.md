## Code

### `fc-core`

- **`events.rs` (new, `pub mod events`)**
  - `Event` enum, as in the table in ADR 0009 part 2. Not `#[non_exhaustive]`. Fields are `Id`s, a
    `Rating`, counts as `u32` and durations as `u32` milliseconds. No field, tag or template text.
  - `Listener` trait: `Send + Sync`, `fn on_events(&self, events: &[Event])`.
  - `Listeners`, a cloneable handle (`Arc<Mutex<Vec<Arc<dyn Listener>>>>`) with:
    - `add`;
    - a crate-only `deliver(&[Event])`, which:
      - does nothing for an empty batch;
      - copies the list out of the mutex, so a listener is never called with that mutex held;
      - calls each listener inside `catch_unwind(AssertUnwindSafe(..))` and ignores a panic.
  - Module docs: the listener rules of ADR 0009 part 3, and a pointer to `docs/events.md`.
- **`Collection`**
  - New fields:
    - `listeners: Listeners`, a fresh one in `finish`;
    - `session: RefCell<Option<OpenSession>>`.
  - `pub fn listen(&self, listener: Arc<dyn Listener>)`.
  - A crate-only `emit_now(Event)` for events that are not writes (sessions, and Phase 4's
    `SyncCompleted`).
  - `close` ends the open session with reason `closed` before closing the connection.
  - Check that `Collection` stays `Send`. `Core` needs that, and `RefCell` is `Send`.
- **`WriteTx`**
  - A crate-only `emit(Event)` that pushes to a `Vec` in the transaction.
  - `Collection::write` delivers that `Vec` after `commit()` succeeds. A rollback drops it.
- **`Core`**
  - Holds a `Listeners`, and gives the collection that handle in `open_collection`, replacing the
    fresh one.
  - `pub fn listen(&self, listener)` adds to it, so a listener added before or after opening hears
    every collection the core opens.
- **Emits**, one line each, inside the existing write closures:
  - `add_note_to_deck` emits `NoteAdded`.
  - `set_note_fields` emits `NoteEdited` only if a field changed or a card was added or removed.
  - `delete_note` emits `NoteDeleted`. The already-deleted branch does not write, so it emits
    nothing.
  - `restore_note` emits `NoteRestored`.
  - `answer` emits `CardAnswered`, with `session` taken from `self.session`.
  - `undo_answer` emits `AnswerUndone`.
  - `merge` emits `MergeApplied` at the end of its closure, built from the `MergeReport`, only when
    `registers_applied + rows_added + unknown_registers + unknown_rows > 0`.
    - Counts are saturated to `u32`.
    - `rejected` is a count.
    - Do not change anything else in the merge.
- **`study/session.rs` (new)**
  - `start_study_session(deck: Option<Id>) -> Result<Id, StudyError>`:
    - ends any open session with reason `replaced`;
    - stores `OpenSession { id, deck, started_ms }`;
    - emits `StudySessionStarted`.
    - A deck that is missing or deleted is `NotFound`.
  - `end_study_session(id) -> Result<Option<SessionSummary>, StudyError>` with reason `ended`.
  - `SessionSummary { answered, again, studied_ms, elapsed_ms }`, all `u32`. One query on
    `card_event` counts reviews where:
    - `device` is this device;
    - `time_ms >= started_ms`;
    - the review is not voided.
  - `EndReason { Ended, Replaced, Closed }`.
- **`Event::SyncCompleted`** has no fields and no caller outside tests.

## Tests

`fc-core`, in `events_tests.rs` and `study/session_tests.rs`. Each uses a recording listener on a
standalone collection.

- Each operation in the table emits exactly its event, with the right IDs, in one batch.
- **No-ops emit nothing:**
  - deleting a deleted note;
  - restoring a live note;
  - an edit with the same values;
  - re-merging the same batch;
  - ending a session that is not open.
- **A failed write emits nothing:**
  - `add_note` to a deleted deck;
  - answering a deleted card;
  - a merge forced to fail (reuse the 1.11a failed-merge test setup).
- **A merge emits one `MergeApplied`**, with counts equal to its `MergeReport`, and no note events.
- **No event contains field text.** Add a note whose field holds a marker string and check that no
  event's `Debug` output contains it.
- **A panicking listener** is caught:
  - the next listener still gets the batch;
  - the next operation works;
  - the panicking listener gets the next batch too.
- **A listener added to a `Core`** before `open_collection` hears the collection's events.
- **Sessions:**
  - start, then three answers (one Again), then undo one: the summary has answered 2 and the right
    Again count;
  - a second start ends the first with `replaced`;
  - `close` ends the open session with `closed`;
  - `CardAnswered` names the session, and has none outside a session.
- **The order** of a batch is the order of emission.

`fc-api`:

- `forward_events` turns each core event into the expected JSON, with one JSON-shape test per
  variant (camelCase, string IDs).
- `debugEmitEvent` still works.

`fc-native`: a hub test that a forwarded core event reaches a subscriber.

## Out of scope

- Events for decks, tags, note types, presets, suspend and bury, media or saved searches.
- API methods for notes, answering or sessions.
- New CLI commands.
- Deleting the debug methods (ADR 0009 part 4).
