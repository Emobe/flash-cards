## 3.2a: core and API for editing and the simple bulk actions

1. **`Collection::edit_note_with(note, values, tags)`** (`note/ops.rs`): `set_note_fields`'s checks
   and writes plus the tag set, one `write`. One `NoteEdited` when anything changed. Answers
   `NoteChange` and the old values and tags of what changed (for undo). `set_note_fields` and
   `set_note_tags` stay.
2. **`delete_notes(&[Id])`, `restore_notes(&[Id])`**: one write each. A note not found refuses the
   whole call; an already deleted (or live) one is skipped. One `NoteDeleted` or `NoteRestored` per
   note that changed. Answer the notes and cards that changed.
3. **Changed sets:** `move_cards` answers each moved card's old deck; `add_tags` and `remove_tags`
   the notes that changed; `suspend_cards` and `unsuspend_cards` the cards that changed. Callers that
   ignore them are unchanged.
4. **Tests (core):** one write each (a failure in the middle writes nothing: digest and row counts),
   only changes written, events once per note, undo inputs correct, a `changes(All)` replay into
   another collection gives the same digest.
5. **`fc-api`** (`crates/fc-api/src/edit.rs`, new): `getNote`, `updateNote`, `searchIds` (every
   match, no limit), `moveCards`, `addTags`, `removeTags`, `suspendCards`, `unsuspendCards`,
   `deleteNotes`, `undoChange`. `target` resolution (`{ notes }` to their live cards, `{ cards }`
   to their notes) in one place. The undo store: one `Mutex<Option<Kept>>` in `Core`, an ID per
   change, replaced by each change. Bindings.
6. **`fc-api` tests** through `dispatch`: each method; a note target on a card action; undo of each
   kind; a second change makes the first token answer "That can no longer be undone."; undo after a
   remote change (the old value still written); no collection open.
7. **CLI:** `edit-note --tag`, `delete-notes`, `restore-notes`; `tests/coverage.rs` rows.
8. **Measure** (release, a throwaway test, in the build notes): `delete_notes`, `suspend_cards`,
   `add_tags` and `move_cards` on 10,000 notes from `fc fake`; `searchIds` at 50,000 cards.

## 3.2b: the note editor

1. **Shell:** a full-screen layer component (a `Dialog` variant, or its own, with the same history
   entry and Escape handling), that owns the insets and has its own `BottomAction`.
2. **`editor/NoteEditor.tsx`:** loads `getNote`, `getNoteTypes`, `getDeckList`, `getTags`. Fields
   through `FieldEditor`, or the HTML text box when `roundTrips` fails (label from ADR 0014). Tags,
   Deck (`moveCards` on save when it changed), duplicate warning without the note itself, Delete.
   Save, Ctrl+Enter, Ctrl+S; "Discard your changes?" on Back and Escape with changes. Reuse the Add
   screen's keyboard handling and toolbar (media buttons too, so a picture can be added while
   editing).
3. **Browse:** tapping a row opens the editor for its note (Cards view: the card's note). After a
   save, the "Saved." notice with Undo and a refresh of the same rows.
4. **Study:** an Edit button next to Undo and `e`. The answer timer stops while the editor is open.
   After a save, `renderCard` again on the same side; if the card is gone, `nextCard`.
5. **Tests (Vitest, fake core):** opening from a row and from Study; a field that does not round-trip
   shows the HTML box, and its text is not changed by a save of another field; save sends only
   `updateNote` once; discard asks only with changes; Back closes; Undo calls `undoChange` and
   refreshes; the deck change calls `moveCards`; Study re-renders, and moves on when the card was
   removed; the timer does not count the editor; no field HTML set with `innerHTML`.

## 3.2c: multi-select and the simple bulk actions

1. **`useSelection`:** a set of IDs, cleared by a mode change; select all through `searchIds`; kept
   after an action, cleared after a delete.
2. **Under 600 px:** Select in the search panel; long press (about 500 ms, `user-select: none`,
   `selectstart` and `contextmenu` cancelled on rows); checkboxes in selection mode; the selection bar
   in `BottomAction` (✕, count, Select all, Move, Tag, Suspend, Delete, More); Android back leaves
   selection mode.
3. **From 600 px:** checkboxes on hover and focus, all shown once one is chosen; Shift+click for a
   range of loaded rows; Ctrl+A for all matching; Escape clears; the bar above the list.
4. **Sheets:** Move (the deck picker from 3.1b, single choice), Tag (add or remove, `TagInput`),
   Delete confirmation with the counts. Suspend toggles by state.
5. **Undo notice** under the bar: the message, Undo, Dismiss; stays until the next change, leaving
   Browse, or Dismiss.
6. **Tests:** entering and leaving selection both ways; long press; tap toggles in selection mode
   and opens the editor otherwise; Shift range; select all uses `searchIds` and shows its count;
   each action sends the right target and IDs; Notes view says "12 notes (18 cards)"; the notice and
   Undo; the selection after an action and after a delete; back leaves selection mode.

## 3.2d: set due date and reset

1. **Migration 12:** nullable `source` and `last_day` on `card_event`, with `adopt_unknown` for both.
2. **`EventKind::SetDue` and `Reset`**, written through `insert_row` with the full recorded result.
   Fold: recorded when built on the last event, recomputed as in ADR 0014 decision 5 otherwise. `void`
   for any kind. `undo_answer` refused after a later `set_due` or `reset`.
3. **`Collection::set_due(cards, from_days, to_days)`** (new cards skipped, the day from the event's
   random bytes in a range) and **`reset_cards(cards)`**, one write each, answering the event IDs and
   the skipped count. `void_events(ids)` for undo, refusing per card as `undo_answer` does.
4. **Stats:** `card_history` lists the two kinds as non-answers; `daily_counts` and `retention` ignore
   them; `optimisation_data` starts a card's item after its last `reset`.
5. **Tests:** every cell of the fold rules (built on, concurrent before and after a review, voided),
   the range spread and its repeatability, new cards skipped, learning card to review, memory kept,
   the next answer's elapsed days, reset then study as new, undo, `undo_answer` refused, merge of both
   kinds into another collection, an older-app reading (an unknown kind with the same columns gives
   the same cache), the v11 upgrade.
6. **`fc-api`:** `setDueDate`, `resetCards`, undo kinds for both. **CLI:** `set-due`, `reset`.
7. **UI:** Set due date sheet (Today, Tomorrow, In N days, Between N and M), the note about new
   cards; Reset confirmation; both in More.

## 3.2e: change note type

1. **`EventKind::Transfer`** with `source` and `last_day`. Fold: always the recorded result.
2. **`Collection::change_note_type(notes, to, fields, templates)`**: one type for all notes (else
   refused), the steps of ADR 0014 decision 6 in one write, a `NoteEdited` per note. Answers what undo
   needs (the reverse maps). Cloze to cloze by number; across kinds no carry.
3. **History and the optimiser** follow `source` in a chain (a cycle guard: stop at a card already
   seen).
4. **Tests:** finding 1's case (Basic to Basic and reversed keeps Card 1's schedule, Card 2 is new),
   field defaults, a field mapped to nothing is emptied, the old values kept, undo restores the old
   cards with study done meanwhile carried back, cloze to cloze, standard to cloze, deck and
   suspension carried, mixed types refused, a merge into another collection gives the same cards and
   schedules, history and optimiser data across a transfer.
5. **`fc-api`:** `changeNoteType`, its undo. **CLI:** `change-notetype`.
6. **UI:** the window (type, field map, card map with defaults, the summary), from More in the
   selection bar and from "Change note type" in the editor.
