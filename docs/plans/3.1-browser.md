Builds ADR 0013 once Accepted, on ADRs 0002, 0003, 0005, 0006 (1.9 build notes) and 0010. Model:
Sonnet build (`/step 3.1`). Where Anthony's review of ADR 0013 changed a decision, the ADR's

## Split

Three stacked PRs, each on its own branch:

| PR | Branch | What |
|---|---|---|

## 3.1a: core and API

1. **Lexer** (`crates/fc-core/src/search/parse.rs`): `Word` records whether the value's first
   character was an unquoted `=`. Inside quotes, `\\` is a backslash (and `\"` a quote, as now). Keep
   `\*` reaching `Pattern` unchanged.
2. **Terms:** `Term::Deck`, `Tag`, `NoteType` and `Card` gain `whole: bool` (strip the `=`). An empty
   name after `=` is a syntax error with the usual "needs a deck after the colon" sentence. Field terms
   are unchanged (`front:=x` is still the text `=x`).
3. **Compile** (`compile.rs`): `whole` uses `Pattern::is_all_of` for decks (on the path; for
   `deckonly:=` the path too, without subdecks), note types and templates. Tags are matched in SQL
   (`fc_has`): add an `fc_tag_is(tag, pattern)` function, or extend the existing one, that is true when
   the folded tag equals the pattern or starts with it followed by `::`. Keep every clause a plain
   true or false (the 1.9 `not` rule).
4. **`SearchRow::detail`** (`run.rs`): the first field after the sort field (by position) whose
   `html::readable` text is not empty, else the first before it, else empty. Read with the per-row
   statement already used for `title`.
5. **Module doc and ADR 0006 notes:** add the `=` rows to the filter table in `search/mod.rs`.
6. **Tests (`search/tests.rs`):** the finding-1 collection (Polish, Polish::Verbs, Irregular Verbs,
   Verbs; tags verbs, verbs::irregular, adverbs; note types Basic and Basic and reversed) with each
   `=` form finding exactly the right cards; `deck:"=x"` still means "contains =x"; case and accents
   ignored with `=`; `*` inside `=`; `\*` and `\\` and `\"` in quoted names (a deck called `a"b*c\`);
   `-deck:="x"`; `deck:=` with nothing is an error; `detail` for Basic, a note whose second field is
   empty, a Cloze note, a field with only `[sound:…]` (what `readable` gives; the screen shows ♪);
   the 300 random boolean queries test still passes.
7. **`fc-api`** (`crates/fc-api/src/search.rs`, new): `search`, `checkQuery`, `getSavedSearches`,
   `saveSearch`, `updateSavedSearch`, `deleteSavedSearch` as in ADR 0013 decision 8. DTOs:
   `SearchSort { key, descending }` with `key` a string union of the ten core names, `SearchMode`
   (`notes`, `cards`), `SearchRowDto` with `due` as a tagged union (`day` with `days: i32` from today,
   `time` with `minutes: i32` from now, rounded up; null for new cards), `total: u32` saturating.
   `checkQuery` answers `{ problem: { message, position } | null }` (position in characters, `u32`).
   Error mapping as in the ADR. Register in the method macro, `cargo xtask bindings`.
8. **`fc-api` tests** through `dispatch`: a search with each sort and both modes; paging; a syntax
   error is `invalidInput` with the core's sentence; `checkQuery` gives the position; due as days and
   minutes (a learning card due in an hour, a review card due in 3 days, one 2 days overdue); saved
   search create, list, update one part, rename to a taken name refused, delete, update a deleted one
   is `notFound`; no collection open.
9. **CLI:** no new command. `fc search` keeps working; check `tests/coverage.rs` needs no row.

## 3.1b: the Browse screen

Files under `packages/ui/src/browse/` unless said otherwise. Only tokens for styling. Every control
meets ADR 0010's target sizes.

1. **`query.ts`:** `type Filters` (deck paths, tag names, note type names, states, one due choice, one
   added choice, one answered choice), `toQuery(filters, text)`, `fromQuery(query) -> { filters, text }`
   and `quote(name)`. Order and shapes exactly as ADR 0013 decision 1 and decision 4.
2. **Fixture:** `browse/query-fixtures.json`, a list of `{ filters, text, query, expect }` (about a
   dozen, covering every chip kind, several values, names with `"`, `*`, `\`, `::`, Polish letters,
   free text with `or`). A Vitest test checks `toQuery(filters, text) === query` and
   `fromQuery(query)` gives back `filters` and `text`. A Rust test in `fc-api` (`include_str!` of the
   same file, path relative to the crate) builds a collection with those names and checks each `query`
   finds exactly the `expect` titles. This is the only cross-language file; say so in a comment at its
   top.
3. **Round-trip property test** in Vitest over generated `Filters` (a small hand-written generator, no
   new dependency).
4. **`useBrowseSearch`:** holds filters, text, sort, mode, seed; debounce 300 ms for text, immediate for
   the rest and for Enter; one call in flight, latest wins, stale results dropped; `checkQuery` on the
   text first; pages of 100 with `loadMore`; refetch on mount, window `focus` and `visibilitychange`;
   "Searching…" only after 300 ms. Remembered in `localStorage` `fc.browse` (try/catch, a bad value
   reads as the default: no filters, empty text, Date added newest first, notes).
5. **`BrowseScreen`** (replaces the placeholder in `screens/placeholders.tsx`): heading and count; the
   list; the search panel in `BottomAction` under 600 px and above the list from 600 px. Add a
   `useMediaQuery` (or `useCompactLayout`) to the shell if none exists, using the same 600 px value as
   `shell.css`. `/` focuses the box (through `useShortcuts`, ignored in text fields). Escape clears
   the text.
6. **`ResultRow`:** title, detail, deck path and the state or due line (`formatDue`, with tests:
   "Due today", "Due tomorrow", "Due in 3 days", "2 days overdue", "In 12 minutes", "Learning",
   "New", plus "Suspended" and "Buried until tomorrow" taking precedence). `[sound:…]` becomes ♪ and a
   leftover image name 🖼 (whatever `readable` leaves; check it in 3.1a's `detail` test). Rows are list
   items with no action in 3.1 (unless Anthony chose the preview, question 6). Empty state: "No cards
   match. Try fewer filters." with a Clear filters button; an empty collection uses the Decks wording.
7. **Chips and pickers:** `ChipRow` (scrolls sideways, edge fade, each chip a button with
   `aria-pressed` and a label that says what is chosen), `PickerDialog` on the shared `Dialog`, styled
   as a bottom sheet under 600 px (a `variant` prop or class on `Dialog`, so other dialogs are
   unchanged). Deck picker: the tree from `getDeckList`, indented, with a filter box. Tag picker:
   `getTags` with a filter box. Note type, State, Due, Added, Answered as ADR 0013 decision 4. A name
   that no longer exists shows "(not found)".
8. **Sort dialog:** the ten sorts with ADR 0013's labels and default directions, a second tap reverses,
   Notes or Cards switch, Shuffle takes a new seed.
9. **Tests (Vitest, fake transport):** typing debounces into one `search` call; a chip runs at once; a
   late older result is dropped; a box mistake shows the message and makes no `search` call; paging
   asks for offset 100; each picker writes the right query; clearing a chip; the remembered state is
   restored and a broken stored value falls back; sort and mode reach the call; the panel is in the
   bottom slot at phone width and at the top when wide (mocked `matchMedia`); `formatDue`; no row text
   is set with `innerHTML` (the row renders a title containing `<b>` as text).
10. **Delete** the Browse placeholder text and its test expectations in `App.test.tsx`.

## 3.1c: saved searches

1. **`SavedSheet`** from the Saved chip: the list by name; tap loads (through `fromQuery`) with its sort
   and mode; Save (name field, the core's refusal shown in the window); with one open and changed,
   Update "name" and Save as new; Rename and Delete per row; Undo after delete saves it again with the
   same values.
2. The open saved search's name shows under the heading, and is remembered in `fc.browse` by ID (a
   deleted one is dropped quietly).
3. **Tests:** load, save, name taken, update, rename, delete and Undo, a saved query typed by hand
   (not in chip shape) opens with everything in the box.

## Checks for every PR

- `cargo xtask check` passes.
- **Web** (`bun run web:dev`, headless Brave at 390 px and 1100 px, light and dark, screenshots read)
  on a collection from `debugAddSampleCards` plus decks and tags made through the UI: typing, each
  chip, sort, notes and cards, paging (needs more than 100 cards: call `debugAddSampleCards` several
  times), no sideways scroll of the page.
- **Desktop** (`bun run dev`, `XDG_DATA_HOME` pointed at a scratch folder): the wide layout, `/`.
- **Phone** (debug APK, taps allowed, never unlock): the bottom panel, typing with the keyboard open
  (the panel above the keyboard, results visible), a picker with its filter box and the keyboard
  open, Android back closing a picker. Time a one-word text search and a chip search on the phone's
  real collection through the UI and write the numbers in the build notes.
- 3.1a has no UI; its phone check is the next APK.
