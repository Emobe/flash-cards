## 1.11a Merge

### Code

- **`sync/changes.rs`**
  - `Changes`, `RegisterChange`, `RowChange` and `Clock { hlc, device }`, as in ADR 0008 part 1.
    `RegisterChange.base` exists from the start and is always `None` in 1.11a.
  - `Selection { All, Unpushed }`.
  - `Collection::changes(selection)`, which reads:
    - `register_clock` joined to each synced table, dynamic table and `unknown_register`;
    - every append-only row (or those in `unpushed_row`), with its columns from
      `unknown_row_value` added back.
  - A register with no clock is not sent.
- **`sync/merge.rs`**
  - `Collection::merge(&Changes) -> Result<MergeReport, CollectionError>`, in one
    `Collection::write`.
  - Crate-only `WriteTx::apply_register(change) -> Applied | Ignored | Unknown | Rejected(reason)`:
    - compares the remote clock with the local one;
    - writes the value, or inserts the row with only that column so the others take their defaults;
    - upserts the clock (`pushed = 1`).
  - Crate-only `WriteTx::apply_row(change)`:
    - `INSERT OR IGNORE`;
    - not added to `unpushed_row`;
    - unknown columns and unknown entities go to `unknown_row_value`.
  - The type check of ADR 0008 part 4, from `pragma_table_info` (declared type and `notnull`), read
    once per merge.
  - The HLC: `hlc_last = max(hlc_last, every received register hlc)`, set before any derived write, so
    reconcile writes stamp after everything received.
  - Then the derived state (ADR 0008 part 5):
    - collect the note IDs and note type IDs whose registers changed;
    - for each changed note type, call `reconcile_note_type`;
    - for each live note not already covered, run a per-note reconcile. It needs a small
      `reconcile_note(w, note)` next to `reconcile_note_type` in `note/generate.rs`, using
      `note_state`, the note type's `Plan` and `dead_decks`;
    - then `rebuild_card` for every card that got a new event, or has an event naming a parameter set
      that just arrived.
  - `MergeReport` (ADR 0008 part 3).
- **`sync/unknown.rs`**
  - `adopt_unknown(tx, entity, names)` for later migrations (ADR 0008 part 6).
  - `store_unknown_register` keeps its public behaviour. Its body is shared with the merge so both
    use one rule.
- **Migration v11:** `unknown_row_value (entity_type TEXT, row_id BLOB, column TEXT, value, PRIMARY KEY
  (entity_type, row_id, column)) WITHOUT ROWID`, added to `LOCAL_TABLES`.
- **Optional, only if it stays small:** switch the hand-written remote helpers in `deck/tests.rs`,
  `study/queue_tests.rs` and `study/fold_tests.rs` to build a `RegisterChange` or `RowChange` and call
  `merge`. Do not change what those tests assert.
- **CLI:** `fc merge <from> <into>` prints the report (applied, ignored, unknown, rejected, notes
  reconciled, cards rebuilt). `fc-cli` test: two files, a note on each, merge both ways, `fc notes`
  shows both on each.

### Tests (`sync/merge_tests.rs`, plus `sync/changes` unit tests)

Helpers:

- `pair()` makes two collections with their own `ManualClock`s.
- `sync(a, b)` merges `a.changes(All)` into `b`, then `b`'s into `a`.
- `digest(c)` covers every synced table, the clocks `(hlc, device)`, every event, `card_schedule`, and
  the results of `decks`, `notes`, `cards`, `tags`, `presets`, `saved_searches` and `media_files`.

Rows of ADR 0006 section 11, one test or more each:

| Row | Test |
| --- | --- |
| Offline for weeks | B makes 200 changes over 3 weeks, A makes newer edits to some of the same registers. After `sync`, A's newer edits survive and every other change of B is there. |
| Same card reviewed on two devices | Good on A and Good 5 minutes later on B, from the same state. Both events are on both, the schedule is identical on both, and the interval is about the single-Good one. Good then Again counts a lapse. |
| Undo of an answer that has synced | A answers, sync, A undoes, sync. B drops the review from its schedule, and the event stays, voided. |
| Same field on two devices | The later HLC wins on both. (The log comes in 1.11b.) |
| Different fields or tags of one note | Both kept. |
| Edit on one device, delete on another | The note is in the trash on both. Restoring it shows the edit. |
| Review on one device, delete on another | The card is in the trash, the review is kept, and restoring brings back the history and schedule. |
| Note added to a deck that is deleted elsewhere | The deck reads as live with only that card. The other cards stay deleted. |
| Note type deleted while notes are added elsewhere | The note type reads as live for those notes. |
| Field removed while a value is edited | The value is kept and hidden, and comes back when the field is restored. |
| Template removed while a card is reviewed | The card is deleted on both and the review is kept. Re-adding the template restores the same card ID with its history. |
| Suspend on one device, review on another | Suspended, and the review counts. |
| Deck options changed on two devices | Field by field. FSRS parameters win whole. |
| Two devices move decks into each other | The cycle is broken the same way on both. |
| Two collections created separately | Built-ins are shared (no duplicate Basic, Default deck or preset). Same-named decks show twice with " (2)". |
| A device clock wrong by hours | B's clock is 3 hours ahead and its edits win. After a merge, A's next write beats every received clock. |
| Two app versions | The "older app" test of ADR 0008 part 11. |
| Local schema migration on one side | Covered by the "older app" test (local only). |
| Interrupted sync | Applying half a batch, then the whole batch, equals applying it once. Applying any batch twice changes nothing. |
| Corrupted database | A new empty collection given `a.changes(All)` has `digest == digest(a)` (apart from its device ID and local-only state). |
| Media | The same bytes added on both devices make one `media_file`. A file deleted as unused on A while B adds a note naming it: after `sync` it reads as alive on both. |
| Card arrives before its note | A batch with only the card registers, then the note: the card is hidden, then shown. |
| Merge-time reconcile | The case in ADR 0008 finding 3 (the reverse card comes back), and a note type template added on A while B adds notes (B's new notes get the new card after `sync`). |
| Unknown event kind and extra event column | Kept, relayed to a third collection unchanged, and the fold treats them as ADR 0007 says. |
| Rejected values | NULL into a NOT NULL register, text into an INTEGER register and a row with a wrong column type are rejected and reported, and the rest of the batch applies. |

## 1.11b Superseded values

### Code

- **Migration v12:**
  - `register_clock` gets `base_hlc INTEGER` and `base_device BLOB` (nullable, no default);
  - new local table `superseded_value (entity_type, entity_id, field, value, hlc, device, by_hlc,
    by_device, PRIMARY KEY (entity_type, entity_id, field, hlc, device)) WITHOUT ROWID`.
- **Registry:** `SyncedTable::kept: &[&str]` and `DynamicTable::kept: bool`, with the list in ADR 0008
  part 7. A registry test checks that every name in `kept` is a register.
- **`WriteTx::record`:** for a kept register, the new `base` is:
  - none, if there is no clock;
  - the current `base`, if the current clock's device is this device;
  - otherwise the current clock.
- **`changes`** fills `RegisterChange.base` for kept registers.
- **`apply_register`:** when a remote change wins over a kept register whose local clock device is
  this device, and `change.base != Some(local clock)`, insert the local value into `superseded_value`
  (`INSERT OR IGNORE`). It then stores `change.base` as the new base.
- **API:**
  - `Collection::superseded_values(filter)` returns entity, ID, register, lost value, its clock and
    the winner's clock;
  - `dismiss_superseded(entity, id, field, clock)`.
- **CLI:** `fc superseded <file>`.

### Tests

- The scenarios behind ADR 0008 finding 1, each as a two-collection test with a fake server:
  - **A pushed, B later and offline** (the case ADR 0006's rule missed): A's text is logged on A.
  - **Concurrent, A's later:** B's text is logged on B.
  - **Sequential edits across devices** (B edits after receiving A's): nothing logged.
  - **A run of edits on one device:** nothing logged on the other device when the run arrives.
  - **Non-kept registers** (suspend, deck parent): never logged.
  - **The same batch merged twice:** logged once.
  - **Dismiss** removes the entry.
  - **Restoring a lost value** through `set_note_fields` writes an ordinary change that syncs.

  The fake server is a `Changes` store that keeps the latest value per register and applies the
  push-after-pull order.
- **A port of the simulation:** three collections, random edits to a few registers, random syncs
  through the fake server. Every conflict loser (computed from recorded bases) is in its own device's
  log. Fixed seeds.
- **Upgrade from a real version-11 layout.**
