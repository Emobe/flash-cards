# Plan: step 1.7 Study queues and answering

Builds ADR 0007 (Accepted 2026-10-06) on ADR 0004 and ADR 0006. Model: Sonnet build (`/step 1.7a`, then `/step 1.7b`).

## Split into two PRs

The step is too large for one review. Each PR has its own migration.

- **1.7a Answering and the schedule** (migration v7): events, the state machine, fuzz, the day
  boundary, the cache and its rebuild, undo. Criteria covered: answering updates scheduling and
  records a review; undo; day boundary configurable and tested across time zones.
- **1.7b Queues** (migration v8): suspend and bury registers, limits over nested decks, card order,
  siblings, counts, next card, the simulated multi-day test. Criteria covered: queues respect limits,
  nested decks and steps; suspend, bury, unbury; the simulated test.

## 1.7a Answering and the schedule

1. **Migration v7.**
   - `options_preset`: add `relearning_steps` (TEXT, default `10`) and `fsrs_parameters` (TEXT,
     default empty). Extend `Preset`, `PresetChange` and the read-time clamping (ADR 0007 part 1).
     `fsrs_parameters` is read only in 1.7 (1.8 writes it); tests write it through `set`.
   - `collection_setting` (synced: `key`, `value`), ID `UUIDv5("fc-setting-1", key)`. API:
     `day_start_hour()` and `set_day_start_hour(0..=23)`, default 0 (midnight).
   - `card_event` and `fsrs_parameter_set` (append-only synced tables, columns as ADR 0007 part 6),
     with guard triggers that refuse INSERT outside the write path and every UPDATE and DELETE.
     Index `card_event (card, time_ms)` and `card_event (time_ms)`.
   - Local: `card_schedule` (ADR 0007 part 9) with an index on `(state, due_day)` and on `due_ms`,
     and a push-state table for append-only rows. Add both to `LOCAL_TABLES`.
   - `sync::registry`: a third table kind for append-only tables. `check_schema` checks their
     columns and triggers. `WriteTx::insert_event` and `WriteTx::insert_parameter_set` (insert or
     ignore) are the only write paths, and mark rows unpushed.
2. **`fc_core::scheduling`** (extend the existing module, keep `fsrs` types private):
   - `study_day(unix_ms, utc_offset_minutes, start_hour) -> i64` with `div_euclid`.
   - The state machine: `(state, step, memory, elapsed_days, rating, steps, relearning_steps,
     scheduler) -> Result` exactly as the table in ADR 0007 part 1. Graduating uses
     `max(1, round(interval))`, then fuzz.
   - `fuzz(interval_days, event_id) -> u32` (part 7). Takes the last 8 bytes of the ID.
   - `ParameterSet` ID from the filled 21 values (part 6).
   - Previews: the four outcomes, unfuzzed, for the answer buttons.
3. **`fc_core::study` (new module)**:
   - `answer(card, rating, duration_ms) -> Answered` (new state, due, interval). Reads the card's
     preset through its deck, inserts the parameter set if new, the event (time rule in part 6,
     `previous` = the cache's last event) and updates `card_schedule`, all in one `write`. Refuses a
     card that is not live. Clamps the duration to 0 to 1 hour.
   - `undo_answer() -> Option<Undone>` (part 10), with an error when the card has a later event.
   - `card_schedule(card)` read model, `card_events(card)` (1.8 builds history on it).
   - `rebuild_schedule()` and the fold (part 9). `schedule_cache_version` in `meta`, checked on
     open.
4. **CLI.** `fc answer <file> <card ID> <again|hard|good|easy>`, `fc undo <file>`, `fc schedule <file>
   <card ID>` (state, due, memory, events). Global `--now <RFC 3339 time>` and `--utc-offset
   <minutes>` on the CLI host clock, so a person can step through days by hand.
5. **Tests (thorough, these are the heart of the app).**
   - The state machine: every cell of the table in part 1, empty steps, empty relearning steps, a
     card on a step the preset no longer has, graduation never below 1 day, the maximum interval.
   - Five Good answers from new with steps `1 10` (two same-day steps, then graduation): pin the due
     days. Check the first interval against finding 1 (S = 2.31, so 2 days before fuzz).
   - Fuzz: the range for several intervals, the same ID gives the same day, no fuzz below 3 days,
     roughly uniform over many IDs.
   - Day boundary: start hours 0, 4 and 23; offsets −720 and +840; a card answered just before and
     just after the boundary; a DST change (offset +60 to +120 mid-run); travelling west so today is
     earlier than the last answer (elapsed days 0); changing the start hour.
   - Events: one per answer with every input and result recorded; immutable (raw UPDATE and DELETE
     refused); event time never before the previous event's when the clock goes back; parameter set
     IDs equal across collections for equal values.
   - Fold: `rebuild_schedule` gives exactly the cache that answering built, over a long random
     sequence; a concurrent pair (two events with the same `previous`, inserted directly) is
     recomputed as ADR 0006 section 4 says; an unknown kind that builds on the previous event applies
     its recorded result.
   - Undo: state, due and memory back to before; repeated undo; refused when the card has a later
     event; a voided review is still stored.
   - Upgrade from a real version-6 layout.

## 1.7b Queues

1. **Migration v8.** `card`: add `suspended` (INTEGER, default 0) and `buried_until` (INTEGER,
   default 0). `deck`: add `limits_include_subdecks` (INTEGER, default 1) with
   `set_deck_limits_include_subdecks`. `options_preset`: add `space_siblings` (INTEGER, default 1),
   part of `PresetChange`. `suspend_cards`, `unsuspend_cards`, `bury_cards`, `unbury_cards`, `unbury_deck`, each
   writing only the cards that change.
2. **Queue (`fc_core::study::queue`)**, computed on each call (ADR 0007 part 5):
   - Candidates in the chosen deck's subtree: live cards, not suspended, not buried today, with the
     siblings rule (part 4) from today's non-voided events, when the card's preset has
     `space_siblings` on.
   - "Done today" per deck from today's events (new: first answer today; review: `state_before`
     review).
   - Limits over the path from the top deck down to the card's deck (part 3), applied greedily in
     card order. A deck with `limits_include_subdecks` off limits only the cards directly in it, and
     does not count or cap its sub-decks.
   - Order (part 4): due learning, then reviews with new cards spread evenly, then learning within
     20 minutes; otherwise `Waiting { until }` or `Done`.
   - API: `study_counts(deck) -> Counts { new, learning, review }`, `deck_counts()` for every deck
     (the deck list), `next_card(deck) -> Next` with the card, its counts and the four previews.
3. **CLI.** `fc due <file> [--deck]` (counts per deck), `fc next <file> [--deck]`, `fc suspend`,
   `fc unsuspend`, `fc bury`, `fc unbury <file> <card ID>...`.
4. **Tests.**
   - Limits: a deck at its new limit, a review limit, a parent limit stopping a child, a child limit
     stopping it inside the parent, studying a sub-deck when the parent is spent, a deck on another
     preset, limits of 0, undo giving the budget back, a parent with "limits include sub-decks" off
     (its own cards limited, its sub-decks not capped and not counted against it).
   - Order: learning before reviews, new cards spread among reviews, creation order for new cards,
     the learn-ahead window, `Waiting` and `Done`.
   - Siblings: held after a sibling's answer today, back tomorrow, lifted by undo, learning siblings
     not held, not held when the preset has `space_siblings` off.
   - Suspend and bury: hidden from the queue and counts, bury lifted by the next day with no write,
     unbury, suspend plus a review from another device (remote registers written with their clocks,
     as 1.5 and 1.6 did).
   - **The simulated multi-day test.** 200 Basic notes in two nested decks, starting values from
     step 1.5. Each day at 09:00 local, study until `Done`, moving the clock forward on `Waiting`.
     Day start at midnight (the default) and once more at another hour. Ratings from a fixed function of `(card ID, answer number)`: about 85% Good, 10% Again, 5% Hard
     and Easy. Record per day: new cards introduced, reviews done, learning answers, and the due
     counts the next morning. Pin the 30-day table, and check invariants alongside (never more than
     the limits, every card introduced by day 10, no review shown before its due day). Run it again
     at offsets −720 and +840 and across a DST change: the table must be identical.
   - Timing (throwaway, not kept, as in earlier steps): `deck_counts` and `next_card` on 50,000 cards.
