# Plan: step 0.6 Sandboxed card rendering spike

For the build session (`/step 0.6`). Builds ADR 0005 once it is Accepted. Do not start before then.

One PR. If it grows past a comfortable review, split it after step 3:

- **0.6a:** the bridge token and the top-frame guard. This is security hardening and stands alone.
- **0.6b:** the card frame, the spike panel and the media path.

Spike code is marked temporary where noted. The token, the `card` scheme, `frame.html` and
`CardFrame` are meant to last.

## Steps

1. **`frame.html`** (new, `packages/ui/src/card/frame.html`). The card-frame page from ADR 0005:
   - The CSP `<meta>`.
   - The bootstrap:
     - it refuses to run unless `self.origin === "null"`;
     - it posts `{ type: "ready" }` to `parent`;
     - it accepts one `{ html, media }` message from `parent`;
     - it parses with `DOMParser` and rewrites `src` on `img`, `audio`, `video` and `source` to
       frame-local blob URLs;
     - it writes the result with `document.open/write/close`;
     - it then reports its height with a `ResizeObserver` (`{ type: "height", px }`).

   Keep it small and dependency-free. It is the trusted part inside the frame.
2. **`fc-native`.**
   - **`card` scheme.** `register_uri_scheme_protocol("card", ...)` serves `frame.html`
     (`include_str!`) at `/frame.html` and returns 404 for anything else. The response has
     `Content-Type: text/html` and a `Content-Security-Policy` header equal to the page's CSP plus
     `sandbox allow-scripts`.
   - **Token gate** (new module `gate.rs`, unit-tested).
     - `issue() -> Option<String>`: a 128-bit random token, Z85 or base64. It returns `None` if a
       token has already been issued.
     - `reset()`.
     - `check(&str) -> bool`: a constant-time comparison.
     - Randomness: use `getrandom`, which is already in the lockfile through Tauri. State why in the
       PR.
   - **`handshake` command.** It returns `gate.issue()`. If none is available, it returns an
     `ApiError` of kind `internal` with the message "The app could not connect to its core. Restart
     the app."
   - **Token checks.** `call`, `subscribe` and `cancel` take `token: String` and reject a bad one
     with the same kind of error before doing anything.
   - **Reset on reload.** `.on_page_load(...)`: on `PageLoadEvent::Started` for the `main` webview,
     call `gate.reset()`. Check by experiment that it fires once per main-frame load and not for the
     card frame. Log it in debug builds while checking. If it also fires for subframes, stop and
     report: the design needs adjusting.
   - **Permissions.** `build.rs`: add `handshake` to `AppManifest::commands`.
     `capabilities/default.json`: add `allow-handshake`. Do not add `core:default` or any plugin
     permission (ADR 0005).
   - **CSP.** `tauri.conf.json`: add `frame-src card: http://card.localhost`.
3. **Tauri transport** (`apps/native/src/tauriTransport.ts`).
   - Start `invoke("handshake")` when the transport is created. Keep the token in a closure.
   - `call`, `subscribe` and `cancel` await it and pass `token`.
   - If the handshake fails, every call rejects with its `ApiError`.
   - The `Transport` interface does not change.
4. **Top-frame guard.** In `apps/native/src/main.tsx` and `apps/web/src/main.tsx`: if
   `window.top !== window`, render nothing and stop before creating the transport.
5. **Media for the spike** (temporary, deleted in 1.10).
   - Add an `fc-api` method `spikeCardMedia { name } -> attachment`, which returns bundled bytes for
     `sample.png` and `sample.wav`, or `notFound`.
   - Make the files ourselves, small and committed: a PNG of a few KB, and a WAV tone of about
     0.5 s. Do not download sample media.
   - Not debug-only, so release web builds can show the sample card. Regenerate the bindings.
6. **`CardFrame`** (`packages/ui/src/card/CardFrame.tsx`, lasting). Props:
   - `html`;
   - `loadMedia(name) => Promise<Blob>`;
   - `mediaNames: string[]`.

   The frame URL comes from a new `PlatformContext` (`{ cardFrameUrl: string }`) provided by each
   app shell. Behaviour, per ADR 0005:
   - a fresh `<iframe sandbox="allow-scripts">` per `html`, with no `allow` attribute;
   - it listens only to messages whose `source` is its own `contentWindow`;
   - on `ready`, it loads the media and posts `{ html, media }` with target origin `"*"` (an opaque
     origin cannot be named);
   - it clamps `height` to between 0 and 10,000 px;
   - it counts `load` events, and from the third on it removes the frame and shows "This card tried
     to open another page and was stopped.";
   - it revokes nothing itself (the frame owns its blob URLs) and drops the frame on unmount.
7. **Spike panel** (temporary, `packages/ui/src/CardSandboxSpike.tsx`, shown in `App` like
   `SchedulingSpike`). Buttons for:
   - **Sample card:** styled HTML, an image, an audio player with a play button, and a JS button that
     reveals a hint and shows a random number.
   - **Malicious card:** one card that tries everything in "Malicious card" below and lists, inside
     itself, each attempt as "blocked" or "SUCCEEDED".
   - **Navigating card:** a card that navigates its own frame to the app URL after 1 s.

   The panel subscribes to core events. If a `debug` event with message `FROM-CARD` arrives, it shows
   a red "A card reached the core" banner. Mobile layout: large tap targets, full-width frame.
8. **Platform wiring.**
   - Native provides `cardFrameUrl = convertFileSrc("frame.html", "card")`.
   - Web provides `/card-frame.html`. A small Vite plugin in `apps/web/vite.config.ts` serves it in
     dev and emits it in build, from the same source file.
9. **Docs.**
   - ADR 0005: "Build notes (step 0.6)" with what was checked on each platform and the timings.
   - ADR 0002: an amendment line pointing to ADR 0005 for card media.
   - README, if a command or prerequisite changed (none expected).
   - STATUS.

## Malicious card

Each attempt reports its own result. Where an attempt needs Tauri internals that are absent (Linux,
web), it reports "no bridge in frame".

- **Bridge:**
  - `__TAURI_INTERNALS__.invoke` for `call` (`debugEmitEvent` with message `FROM-CARD`), with no
    token and with a guessed token;
  - `handshake`;
  - `subscribe` with a new `Channel`;
  - `cancel`;
  - `plugin:event|emit`;
  - `plugin:__TAURI_CHANNEL__|fetch`;
  - raw `window.ipc.postMessage` and `window.webkit.messageHandlers.ipc.postMessage` with made-up
    payloads.
- **Parent and top:**
  - read `parent.document`;
  - read the frame's own `parent.frames`;
  - assign `top.location`;
  - `window.open`;
  - a form with `target="_top"`;
  - click an `<a target="_top">`;
  - `postMessage` a huge `height` and unknown message types.
- **Storage:** `localStorage`, `sessionStorage`, `indexedDB`, `caches`, `document.cookie`,
  `navigator.storage.getDirectory()`.
- **Network:**
  - `fetch` and `XMLHttpRequest` to the app origin, `ipc://localhost`, `http://ipc.localhost` and
    `https://example.com`;
  - `WebSocket`;
  - `navigator.sendBeacon`;
  - `<img>`, `<link rel=stylesheet>` and `<script src>` pointing at the app origin and a remote
    host.
- **Prompts and permissions:** `alert` and `confirm`, `requestFullscreen`, geolocation,
  `getUserMedia`, `navigator.clipboard.readText`, `Notification.requestPermission`.

Not automated: an infinite loop. It would freeze the app (a known limit in ADR 0005). Check it once
by hand on desktop, record what happens, and do not put it in the panel.

Review focus says to try to break it. Add any further attempts you think of, and list them in the
PR.

## Tests

- **Rust:**
  - gate: issue once, a second issue fails, reset allows a new token, check accepts only the issued
    token;
  - each command rejects a missing or wrong token (test the shared check function the commands
    call);
  - `spikeCardMedia` returns bytes and `notFound`;
  - the bindings test.
- **TS, `CardFrame` with jsdom:**
  - posts `{ html, media }` only after `ready` from its own frame;
  - ignores messages from other sources;
  - clamps `height`;
  - removes the frame and shows the message on the third `load`;
  - a new `html` creates a new iframe;
  - the iframe has exactly `sandbox="allow-scripts"`.
- **TS, Tauri transport (mocked `invoke`):**
  - the token from `handshake` is passed to `call`, `subscribe` and `cancel`;
  - a failed handshake rejects calls with its message.
- Existing tests pass.

## Manual checks (record in the PR and ADR 0005 build notes)

- **Desktop (Linux),** in the built debug app (`tauri build --debug --no-bundle`), because the CSP
  only applies there (ADR 0002 build notes), and in `bun run dev`:
  - the sample card renders with the image, plays audio and runs its JS;
  - every malicious attempt is blocked and no "reached the core" banner appears;
  - the navigating card is removed.
- **Android,** on the phone with `bun run android:build` then `bun run android:install`, plus
  screenshots: the same checks. This is the key platform: the card frame has the bridge and the
  invoke key there (ADR 0005, finding 2), so the token must be what stops it. Confirm that the
  malicious card's `call` attempt produces **no** event.
- **Web,** with `bun run web:dev` (and `web:build` with `web:preview`) in headless Brave (scratch
  script, not committed): the same checks.
- **Reload:** after a reload of the main webview (desktop dev live reload, or the WebView's reload),
  the app handshakes again and works.
- **Timing:** record the time from mounting `CardFrame` to the first `height` message for the sample
  card, on desktop and on the phone (median of 10).
- `cargo xtask check` passes.

By Anthony (optional): open the spike panel on the phone and in his desktop browser and press the
buttons. Windows, Firefox and Safari stay unverified and are listed as such.
