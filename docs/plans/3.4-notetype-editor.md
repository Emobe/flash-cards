## 3.4a: core and API

1. **Draft type** (`notetype/draft.rs`, new): `Draft { name, css, sort_field: Option<DraftRef>,
   fields: Vec<DraftField { id: Option<Id>, name }>, templates: Vec<DraftTemplate { id:
   Option<Id>, name, front, back }> }`. `sort_field` names a field by index in the draft. A draft
   item with an ID that is removed in storage means "restore it".
2. **`Collection::save_note_type(id, &Draft) -> SaveOutcome`**: the checks of ADR 0006 build notes
   1.2 against the draft (names, at least one of each, cloze has one template, the template syntax),
   then one `write`:
   - registers that differ only;
   - new items with new IDs; items missing from the draft removed; removed items in the draft
     restored;
   - positions: keep the longest increasing subsequence of the old order, give the rest
     `position::between` their new neighbours (renumber only if there is no room, as `move_part`
     does);
   - one `reconcile_note_type`, counting cards added and removed;
   - answer the old values of every register written (for undo) and the counts.
3. **`note_type_consequences(id, &Draft)`**: the same checks, no write; a `Plan` from the draft
   against each live note's live cards; answers cards added, cards removed, notes affected.
4. **`preview_card(&Draft, template_index, note: Option<Id>, ordinal)`**: `template::render` with
   the draft (no note: each field's value is `(Name)`); answers `RenderedCard`, whether the note
   makes this card with the draft, or the problems and unknown field names. No write.
5. **`copy_note_type(source, name)`**: new IDs, same names, text, styling, sort field (mapped), one
   write. **`template::rename_field`** made public (a thin wrapper if the internal one is
   `pub(crate)` for a reason).
6. **Undo:** `Reverse::NoteTypeSave { note_type, registers: Vec<(entity, id, register, old value)> }`
   (write back, then reconcile), `Reverse::DeleteNoteType(id)` (for create) and
   `Reverse::RestoreNoteType(id)` (for delete).
7. **Tests (core):** each kind of change alone and all together; only changed registers get new
   clocks; a failure part-way writes nothing (digest); the dry run's counts equal what a save then
   does; a template whose front becomes empty sends cards to the trash and undo brings back the same
   IDs with history; a rename in the draft keeps values; positions: reorder one field writes one
   position; two collections reordering different fields, merged both ways, converge and keep both
   moves; `changes(All)` replay converges; preview with no note, a cloze note per number, a draft
   with a mistake, a renamed field.
8. **`fc-api`** (`crates/fc-api/src/notetypes.rs`, new): `getNoteTypeDetails`,
   `renameFieldInTemplates`, `previewNotes`, `previewCard`, `checkNoteType`, `saveNoteType`,
   `createNoteType`, `deleteNoteType`; `noteCount` added to `getNoteTypes`; the new reverses in
   `undoChange`. Bindings. Tests through `dispatch`, including undo of each and "That can no longer
   be undone." after another change.
9. **CLI:** `notetype copy`, `notetype save <name> @draft.json`, `notetype check <name>
   @draft.json`, `notetype preview <name> --template <n> [--note <id>]`; `tests/coverage.rs` rows.
10. **Measure** (release, throwaway, in the build notes): `save_note_type` and
    `note_type_consequences` changing Basic's front on the 10,000-note `fc fake` collection;
    `preview_card` once.

## 3.4b: the note type screens

1. **Routes** `notetypes` and `notetypes/<id>` under the Settings destination; a "Note types" row in
   Settings; "Manage note types" in Add's note type picker.
2. **`screens/notetypes/NoteTypeList.tsx`:** name, kind, notes; New note type (name, Start from: a
   copy of any type, or Basic or Cloze shapes when none is left).
3. **`screens/notetypes/NoteTypeScreen.tsx`:** the draft in a reducer (`draft.ts`, unit tested):
   name; Fields and Cards rows with the sheet under 600 px and row buttons from 600 px (Rename, Move
   up, Move down, Use to sort, Edit template, Remove); Add field, Add card (copy of the first);
   Removed fields and cards with Restore; Delete note type with counts and Undo. A rename calls
   `renameFieldInTemplates` and replaces the draft's templates.
4. **Save:** local checks with the reason next to the problem; `checkNoteType`; the trash question
   when `cardsRemoved > 0`; "Saving…"; `saveNoteType`; the notice "Saved Polish words." (with "120
   new cards." when there are any) and Undo. Ctrl+S. "Discard your changes?" on Back and Escape.
5. **Edit template** and **Styling** are not shown in 3.4b. 3.4c adds them, so no button leads
   nowhere in between.
6. **Tests:** reducer, list, rename rewriting, Save paths (no question, the trash question, a
   refusal), Undo, Discard, both widths.

## 3.4c: the template editor and live preview

1. **`TemplateEditor.tsx`**, a full-screen layer (the one from ADR 0014) over the note type screen,
   editing the draft held by `NoteTypeScreen`: tabs Front, Back, Styling; Done.
2. **The textarea** with the attributes in ADR 0015 decision 3. **Insert row** (fields,
   `{{FrontSide}}` on Back, `{{cloze:…}}` on cloze types, Show if… wrapping the selection), in
   `BottomAction` under 600 px.
3. **Mistakes and warnings** from `previewCard`, under the box; tapping one sets the selection to
   that line and column.
4. **`TemplatePreview.tsx`:** `previewNotes`, Previous and Next, cloze number picker, Front and
   Back, `CardFrame` with media through `getMedia` and the app's theme; debounce 400 ms; keep the
   last good render dimmed while there is a mistake; double-buffer (keep the old frame until the new
   one sends `ready`); the "no notes" and "makes no card" lines.
5. **Layout:** two columns from 840 px; under 840 px the Edit / Preview switch, Preview closing the
   keyboard (blur), Edit restoring the selection.
6. **Tests:** inserts at the cursor and wrapping, the debounce, a mistake keeps the last preview,
   switching sides, no notes, cloze numbers, Done keeping the draft.
