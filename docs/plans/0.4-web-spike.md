# Plan: step 0.4 Web client spike

For the build session (`/step 0.4`). Builds ADR 0003 once it is Accepted. Do not start before then.

One PR. It is one coherent change (the core running and storing data in the browser). If it grows
past a comfortable review, split it at step 5: 0.4a (storage, `fc-wasm`, xtask) and 0.4b
(`apps/web` and the transport).

Spike code is marked temporary where noted and deleted in step 1.1. The transport, worker, `fc-wasm`
and build commands are meant to last into Phase 6.

## Steps

1. **Toolchain.** Add `targets = ["wasm32-unknown-unknown"]` to `rust-toolchain.toml`. README
   prerequisites: `cargo install wasm-bindgen-cli --version 0.2.129 --locked`, clang with the wasm32
   target (the Manjaro `clang` package works; Windows unverified, note it).
2. **`fc-core` storage (temporary).** Add `rusqlite = "=0.40.2"`, with the `bundled` feature only
   for `cfg(not(target_arch = "wasm32"))` so the web uses `sqlite-wasm-rs`. A `spike` module:
   `SpikeStore` opens a path or URI, creates `notes(id INTEGER PRIMARY KEY, body TEXT NOT NULL)`,
   adds and lists notes. `Core::new()` is unchanged. Add `Core::open_spike(uri)`, which holds the
   store in a `Mutex` so `Core` stays `Send + Sync`. Unit tests use an in-memory database. Marked for
   deletion in 1.1.
3. **`fc-api`.**
   - Temporary methods `spikeAddNote { text } -> SpikeNotes` and `spikeListNotes -> SpikeNotes`
     (`{ notes: string[] }`). With no store open: `notFound`, "No collection is open." Text over
     1,000 characters or empty: `invalidInput`.
   - `debugSlow` must not call `thread::sleep` on wasm (ADR 0003, finding 9). On
     `cfg(target_arch = "wasm32")`, busy-wait on `js_sys::Date::now()` instead. `js-sys` is a
     wasm-only dependency of `fc-api`, used only by debug code, and is removed with the debug methods
     in 1.12.
   - Add debug method `debugPanic` (panics). It checks the trap path on the web and the
     `internal` path on native.
   - Regenerate the bindings.
4. **`crates/fc-wasm`** (new). `#![forbid(unsafe_code)]`. All dependencies under
   `[target.'cfg(target_arch = "wasm32")'.dependencies]`, and on native the lib is empty.
   Dependencies: `fc-api`, `serde_json`, `wasm-bindgen = "=0.2.129"`, `wasm-bindgen-futures`,
   `js-sys`, `sqlite-wasm-rs = "=0.5.5"`, `sqlite-wasm-vfs = "=0.2.0"`. Exports:
   - `init(onNotice: Function)` stores the callback in a `thread_local` and installs a panic hook
     that logs to `console.error`.
   - `async open(name)` installs `opfs-sahpool` (not as the default VFS) and opens
     `file:{name}?vfs=opfs-sahpool` through `Core::open_spike`.
   - `call(method, input: string, bytes: Option<Vec<u8>>, op: Option<u32>)` returns
     `{ output: string, bytes: Uint8Array }` or throws the `ApiError` as a JSON string. The
     `OpContext` cancel closure is `|| false`. The sink is a zero-sized `EventSink` that calls the
     stored callback with the notice as JSON.
5. **xtask.**
   - `cargo xtask wasm [--release]`: check that `wasm-bindgen --version` equals the
     `wasm-bindgen` version in `Cargo.lock`, otherwise stop with the install command. Then
     `cargo build -p fc-wasm --target wasm32-unknown-unknown`, then
     `wasm-bindgen --target web --out-dir apps/web/src/wasm`. `apps/web/src/wasm/` is gitignored.
   - `check`: add `cargo clippy -p fc-wasm --target wasm32-unknown-unknown -- -D warnings`, and run
     `xtask wasm` (debug) before `tsc` so the generated `.d.ts` exists. Update the usage text.
6. **`apps/web`** (new Bun workspace member, Vite `8.3.2` and React matching `apps/native`).
   - `src/core.worker.ts`: loads the wasm, calls `init` and `open("collection.db")`, answers
     `{ id, method, input, bytes }` messages and posts notices. Throttles progress the way
     `fc-native`'s hub does.
   - `src/webTransport.ts` implements `Transport` as ADR 0003 describes: a main-thread queue, one
     request in flight, attachment buffers transferred, and `cancel` that removes a queued call or
     terminates and restarts the worker. A trap rejects with `internal` and restarts. `open` is
     retried every 50 ms for up to 5 s. If it still fails, every call rejects with
     `internal`: "The collection is open in another tab. Close the other tab, then reload this
     one." Takes a worker factory, so tests can use a fake worker.
   - `src/main.tsx`: mounts the shared `App` from `packages/ui` with `CoreProvider` and the web
     transport. Calls `navigator.storage.persist()` once.
   - `src/SpikePanel.tsx` (temporary, lives in `apps/web` only): add a note, list notes, show
     `persisted` and `estimate()`. Large tap targets, usable at phone width.
   - Scripts: root `web:dev` (`cargo xtask wasm && vite`) and `web:build`
     (`cargo xtask wasm --release && vite build`), plus `web:preview`.
   - Add it to TypeScript project references, Biome and the Vitest projects.
7. **Docs.** ADR 0001 amendment: `crates/fc-wasm` and `apps/web` added, and the "core as a wasm
   package under `packages/`" assumption answered with no, because the glue is generated into
   `apps/web`. README: prerequisites and web commands. CLAUDE.md: add `bun run web:dev`. ADR 0003:
   "Build notes (step 0.4)" with measurements. STATUS.

## Tests

- Rust: spike store add and list (in-memory), the `notFound` and `invalidInput` messages, dispatch
  of both spike methods, `debugPanic` panics when dispatched (native turns the
  panic into `internal` through `spawn_blocking`'s join error, checked by hand), bindings test.
- TS, `webTransport` with a fake worker: a call resolves; an `ApiError` rejects as `CoreError`;
  calls run one at a time in order; cancelling a queued call rejects it without reaching the
  worker; cancelling the running call terminates the worker, rejects with `cancelled` and later
  calls succeed on the new worker; a trap rejects with `internal` and restarts; attachments are
  transferred (the source buffer is detached); progress reaches the right caller; `open` failure
  gives the other-tab message.
- The existing `CoreClient` tests still pass unchanged.

## Manual checks (record in the PR and ADR 0003 build notes)

By the build session, using a headless Brave script in the scratch directory (not committed), as in
the design experiment:

- `bun run web:build`, serve `dist` with `bun run web:preview`. Add notes. Reload: notes are still
  there. Kill the browser and start it again with the same profile: notes are still there.
- `debugSlow` shows progress. Cancelling it rejects with `cancelled`, and the core answers again
  after the restart (note how long the restart takes).
- `debugPanic` gives the readable `internal` message and the core answers again.
- A second tab shows the other-tab message.
- `getCoreInfo` and the divide form work as on native.
- The desktop app still works (`bun run dev`). `cargo xtask check` passes.

By Anthony (optional, in the PR's test section): the same add, reload and restart in his own
desktop browser. Firefox and Safari are unverified and stay listed as such. Mobile browsers need
HTTPS for OPFS and are out of scope for the spike.
