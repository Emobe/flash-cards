## 2.7a: app identity

1. **Version.** `[workspace.package] version = "0.1.0"`; every crate `version.workspace = true`.
   Remove `version` from `tauri.conf.json`; check the built app and `tauri.properties` still say
   `0.1.0` (versionCode 1000). If Tauri does not fall back to Cargo's version, stop and say so.
2. **Build ID.** A small helper in `scripts/lib/` (git short commit, `-dirty` when `git status
   --porcelain` is not empty, `dev` when Vite runs the dev server). Both `apps/native` and `apps/web`
   Vite configs define it; each `main.tsx` passes it to `<App build=…>`; `App` hands it to
   `SettingsScreen`.
3. **Settings.** An "About" group at the end: "Version {coreVersion} ({build})", from `getCoreInfo`.
   Test: the group renders the version and build from a fake core; it shows nothing broken while the
   call is pending or fails.
4. **App ID.** `<APP_ID>` in `tauri.conf.json`, `namespace` and `applicationId` in
   `app/build.gradle.kts`, the Kotlin package line and folder (`git mv` the
   `java/dev/placeholder/flashcards` sources to the new path), `ANDROID_PACKAGE` in `appearance.rs`.
   `git grep -i placeholder` afterwards lists only docs.
5. **Dev builds.** `bundle > android > debugApplicationIdSuffix: ".dev"`;
   `src/debug/res/values/strings.xml` with `app_name` "Flash cards dev"; `scripts/dev.ts` passes
   `--config` with the `.dev` identifier and the "Flash cards dev" window title; `scripts/lib/adb.ts`
   `APP_ID` is `<APP_ID>.dev`. Check `bun run android:dev` and `android:build` +
   `android:install` start the `.dev` app (finding 9 is unverified). If the CLI launches the wrong ID,
   stop and say so.
6. Checks: `cargo xtask check`; `bun run dev` shows "Flash cards dev" and a new empty data folder
   (`~/.local/share/<APP_ID>.dev`); the phone gets "Flash cards dev" next to the old app. Screenshots
   of Settings at phone and desktop widths.

## 2.7b: release builds

1. **Linux fix.** `main.rs`: on Linux, if `WEBKIT_DISABLE_DMABUF_RENDERER` is not set, set it to `1`
   before `run()`, in an `#[allow(unsafe_code)]` block with a `SAFETY` comment (no other thread yet).
   `apps/native/src-tauri/Cargo.toml` replaces `[lints] workspace = true` with a copy of the workspace
   table where `unsafe_code = "deny"`. Remove the variable from `scripts/dev.ts` and check `bun run
   dev` still renders. README troubleshooting entry updated.
2. **Bundle metadata.** `mainBinaryName: "flash-cards"`, `bundle.shortDescription`, a
   `longDescription`, `category`. Check the `.desktop` file.
3. **`bun run dist:linux`** (`scripts/dist-linux.ts`): `tauri build --bundles deb`, then `makepkg -f`
   in a copy of `packaging/arch/` (the `PKGBUILD`: `pkgver` from the version, depends `webkit2gtk-4.1
   gtk3 gst-plugins-base gst-plugins-good`, `package()` unpacks the `.deb`'s `data.tar.gz`). Accept
   any `PKGEXT` (Anthony's `~/.makepkg.conf` makes `.pkg.tar.xz`). Copy both into `release/` as
   `flash-cards-<version>-linux-x86_64.{deb,pkg.tar.*}`. `release/` in `.gitignore`.
4. **Android signing.** Tauri's `signingConfigs` in `app/build.gradle.kts` (as in finding 6). Missing
   `keystore.properties` makes the release build fail with a message naming the README section.
5. **`bun run dist:android`** (`scripts/dist-android.ts`): `tauri android build --apk --target
   aarch64`, copy to `release/flash-cards-<version>-android-arm64.apk`.
   **`bun run dist:android:install`**: `adb install -r` that file and start `<APP_ID>`.
6. **Windows workflow** `.github/workflows/windows-installer.yml` as in decision 5 (pin every action
   by SHA, `permissions: contents: read`, `workflow_dispatch` with no other trigger, NSIS only,
   artifact retention 30 days). **`bun run dist:windows`** (`scripts/dist-windows.ts`): refuses if the
   branch is not pushed or has unpushed commits, then `gh workflow run`, `gh run watch`,
   `gh run download` into `release/`. Push over HTTPS as CLAUDE.md says.
7. **README:** the "Dogfood builds" section (decision 7). Also the version-bump rule.
8. **Checks:**
   - `cargo xtask check`.
   - Linux: `dist:linux`; run the built binary with no variable set and with empty `XDG_*` folders,
     screenshot. Anthony installs the pacman package and checks it starts from the menu, then that a
     card with sound plays.
   - Android (after Anthony's key exists): `dist:android` and `dist:android:install`; the app starts
     and is not debuggable (`dumpsys package`). Ask Anthony to switch the theme once (the
     `AppearancePlugin` under R8) and to move his data with Export and Restore from a file.
   - Windows: one `dist:windows` run; Anthony installs on Windows and reports. If the workflow fails
     on Windows-specific code, fix it in this PR if small, otherwise stop and say so.
   - The version in Settings on all three, matching the file names.
